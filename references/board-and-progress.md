# The board, and keeping progress safe

The board is where the learner lives: "integrating with board itself will give me more motivation because everything is being tracked there". It's a claude.ai artifact built from `assets/board/index.html`. Before writing or changing the page, load the `artifact-design` and `artifact-capabilities` skills; the page declares the `db` and `user` capabilities.

## What's on it

- **Header:** title, eyebrow, lede and the build route (from `track.json`), four meters (one per track plus Feature), and an **Up next** card that always points at the next concept or build step.
- **Journey:** milestones, each opening to its lessons ("Learn") and build steps ("Build"), with a balance line "Learn a/b · Build c/d". Lessons open in place: concepts first, then Practice.
- **Topics:** every topic in the map, grouped by track, with a state and filters. A taught topic links to its concept.
- **Feature:** capabilities and build steps with their states.
- **Notes:** every note the learner wrote, in one place.
- **Decisions:** open questions and decided items from both requirement documents, labelled product or learning, plus both documents in full.
- **Log:** `log.md`.

Each concept reads straight through in the language being learned (Example → Explain → More → Takeaway). The comparison with the known language sits below it, **collapsed**, as "Compare with <Name>". It stays open once the learner opens it (remembered in the browser). Every concept has an **"I understand this"** tick and a **note box**, and so does every exercise. Each lesson has **Skip** (reversible, doesn't count as learned) and **Test out** (answer its predict and choice questions first; all right means learned).

**Topic states:**
- `ready`: its lesson exists.
- `understood`: ticked.
- `practised`: an exercise practising it passed.
- `learned`: both, or tested out.

Side states are `skipped`, `planned` (no lesson yet), `bonus` and `not planned`.

## Where its data comes from

| Data | Where it lives | Written by |
|---|---|---|
| The page | `board/index.html` (from the template, `<title>` replaced with the track's title) | Claude |
| Lessons, curriculum, docs, log | `board/content.json`, **generated by lessoncheck** | the checker, from files Claude writes |
| Ticks, answers, hints used, notes, skip/test-out | the artifact's database: collections `concepts/{topicId}`, `exercises/{exerciseId}`, `lessons/{lessonId}` | the learner, by clicking |
| A copy of those clicks | `progress/` in the learning folder | Claude, at the end of every session |

**Only clicks go in the database.** Anything Claude writes is a file, so it can be read, diffed and checked. The database is a single store on claude.ai, and deleting the artifact erases it. That's why the progress copy exists.

## Publishing

1. Run `go run ./tools/lessoncheck` in the learning folder. It must print `lessoncheck ok`, and it writes `board/content.json`.
2. The Artifact tool only publishes files from Claude's working folder or scratchpad. If the learning folder is elsewhere (it usually is; see where-things-live.md), copy `board/index.html` and `board/content.json` to the scratchpad first.
3. Publish `index.html` with `files: {"content.json": <path>}`.
   - **First time:** pass `icon` and `capabilities: {"db": {}, "user": {}}`.
   - **After that:** pass the artifact's `url` so the link stays the same, and omit `capabilities` to keep them.
4. After the first publish, list each collection once with ArtifactData, to confirm it's readable. Check that `content.json` shows up in `list` with `scope: "files"`.

Record the board URL in the learning folder's plan and in memory.

## The progress copy (end of every session, not optional)

The learner's rule was "nothing being lost", and notes are the most personal thing they produce. At the end of every working session:

1. Clear a scratch folder, then `ArtifactData list` each of `concepts`, `exercises` and `lessons` with `out_dir` set to that folder (one JSON file per document).
2. From the learning folder: `go run ./tools/progress -raw <that folder>`.
3. This writes:
   - `progress/notes.md`: readable, grouped by milestone and lesson, with a summary line;
   - `progress/progress.json`: everything, latest;
   - `progress/snapshots/<date>.json`: one per day, so an earlier state can be restored.
4. Add a line to `log.md` if something notable happened, then re-run the checker and republish, so the Log tab updates.

**Restore** (if the board's database is ever lost or a note overwritten): read `progress.json` or a snapshot and write it back with an `ArtifactData batch` (`set` per document, at most 50 per batch).

While you're there, read the learner's notes. They show what landed and what didn't. A note like "so basically go lang is a compiled type language not a run time" deserves a sentence back confirming it or sharpening it.
